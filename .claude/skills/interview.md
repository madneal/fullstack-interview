# 面试题目生成

根据候选人简历，生成一轮完整的面试题目（15 道）。

## 输入

用户提供候选人简历，支持以下方式：
- 文件路径（PDF、Markdown、文本文件）
- 直接粘贴简历文本

如果用户没有提供简历，提示用户提供。

## 流程

### 第一步：分析简历

阅读简历，提取以下信息：
- **工作年限和资历等级**（初级 / 中级 / 高级）
- **技术栈**（语言、框架、基础设施）
- **安全相关经验**（安全开发、渗透测试、应急响应、安全运营、AI 安全等方向）
- **项目经历中的关键声明**（负责的系统、解决的问题、达成的指标）
- **简历中可以深挖或验证的点**（模糊的描述、值得追问的亮点、可能夸大的部分）

### 第二步：从题库选 10 道题

读取题库文件 `精选面试题库.md`（位于项目根目录）。

选题规则：
1. **必选项目经历题**（第 1 题），作为开场
2. **必选至少 2 道代码审计题**（第三板块），优先选候选人熟悉语言的题目
3. **必选至少 1 道场景题**（第四或第七板块）
4. 剩余题目根据候选人方向和资历从以下板块选取：
   - 安全基础（第二板块）：根据候选人技术栈选择相关题目
   - AI/MCP 安全（第五板块）：如果候选人有 AI 相关经验
   - 工程能力（第六板块）：根据实际需要
5. **难度匹配**：初级候选人侧重基础概念和简单代码审计；高级候选人侧重多分支代码审计、架构设计和场景分析
6. **避免全部选同一漏洞类型**，覆盖面优先

对每道选中的题目，输出原题的完整内容（包括代码和参考要点）。

### 第三步：根据简历生成 5 道题

围绕候选人简历中的具体内容生成 5 道定制题目，每道包含题目、参考要点和追问。

生成规则：
1. **至少 2 道针对项目经历**：基于简历中描述的具体系统或成果提问，验证候选人是否真正深入参与。例如简历写"负责 WAF 规则优化"，就问具体优化了哪类规则、误报率如何衡量、回退策略是什么
2. **至少 1 道针对技术声明**：验证候选人声称掌握的技术。例如简历写"熟悉 Kubernetes 安全"，就问 Pod Security Standards 的具体约束
3. **至少 1 道针对可疑或模糊描述**：简历中笼统的表述（"参与安全建设"、"负责安全体系"）需要通过具体问题验证深度
4. 每道题必须有**参考要点**（候选人应该能说出什么）和**追问**（如果答得好怎么深挖）
5. 题目风格和深度与题库保持一致

### 第四步：输出面试方案

按以下格式输出完整方案：

```
## 候选人概况

- 姓名：
- 资历判断：初级 / 中级 / 高级
- 主要方向：
- 技术栈：
- 需要重点验证的点：

## 题库题目（10 道）

按建议的面试顺序排列，每道标注：
- 题号和完整题目
- 选题理由（一句话说明为什么选这道）
- 建议时间
- 参考要点（从题库复制）
- 追问（从题库复制）

## 简历题目（5 道）

每道标注：
- 题目
- 简历依据（引用简历原文）
- 参考要点
- 追问
- 建议时间

## 时间分配

总计约 60 分钟：
- 开场和项目经历：10 分钟
- 题库题目：30 分钟
- 简历题目：15 分钟
- 候选人提问：5 分钟

## 判断标准

列出 3-5 个该候选人的关键判断维度，以及对应的通过/不通过信号。
```

## 注意事项

- 题目输出使用中文
- 代码题保留原始代码块，不要省略
- 参考要点是给面试官的参考，不是标准答案，面试时不要念出来
- 简历生成的题目要具体到候选人的经历，不要生成通用题目
- 如果简历信息不足以生成 5 道定制题，用 3 道定制题 + 2 道从题库额外选取补充
